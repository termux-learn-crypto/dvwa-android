Help - Cross Site Request Forgery (CSRF)

Parichay (About)

CSRF ek aisa attack hai jo ek end user ko kisi web application par unwanted actions execute karne ke liye force karta hai jisme woh currently authenticated hota hai. Thodi si social engineering ki help se (jaise email ya chat ke through koi link bhejna), ek attacker kisi web application ke users ko attacker ki pasand ke actions execute karne ke liye force kar sakta hai.

Ek successful CSRF exploit normal user ke case mein end user ka data aur operation compromise kar sakta hai. Agar target kiya gaya end user administrator account hai, toh yeh poori web application ko compromise kar sakta hai.

Is attack ko "XSRF" bhi kaha ja sakta hai, jo ki "Cross Site Scripting (XSS)" ke jaisa hai, aur yeh aksar ek saath use hote hain.



Objective (lakshya)

Aapka task hai ki current user se uska password change karwaya jaye, bina usko apni actions ke baare mein pata chale, ek CSRF attack ka use karke.



Low Level

Is attack se bachne ke liye koi measures nahi hain. Iska matlab hai ki ek link craft kiya ja sakta hai koi specific action perform karne ke liye (is case mein, current user ka password change karna). Fir thodi basic social engineering ke sath, target ko link par click karwaya jata hai (ya bas ek specific page visit karwaya jata hai), taaki action trigger ho jaye.

Spoiler (jawab): ?password_new=password&password_conf=password&Change=Change.

Medium Level

Medium level challenge ke liye, ek check lagaya gaya hai ki last requested page kahan se aaya tha. Developer ka maanna hai ki agar yeh current domain se match karta hai, toh yeh web application se hi aaya hoga isliye is par trust kiya ja sakta hai.

Is vector ko exploit karne ke liye ho sakta hai ki multiple vulnerabilities ko link karna pade, jaise ki reflective XSS.


High Level

High level mein, developer ne ek "anti Cross-Site Request Forgery (CSRF) token" add kar diya hai. Is protection method ko bypass karne ke liye, ek aur vulnerability ki zarurat padegi.

Spoiler (jawab): e.g. Javascript is a executed on the client side, in the browser.

Bonus Challenge

Is level par, site change password request ko ek JSON object ke roop mein bhi accept karegi niche diye gaye format mein:

{"password_new":"a","password_conf":"a","Change":1}

Jab is tarah se kiya jaye, toh CSRF token ko user-token naam ke header ke roop mein pass karna hoga.

Yahan ek sample request hai:

POST /vulnerabilities/csrf/ HTTP/1.1
Host: dvwa.test
Content-Length: 51
Content-Type: application/json
Cookie: PHPSESSID=0hr9ikmo07thlcvjv3u3pkfeni; security=high
user-token: 026d0caed93471b507ed460ebddbd096

{"password_new":"a","password_conf":"a","Change":1}

Impossible Level

Is level par, site user se uska current password aur naya password dono maangti hai. Kyunki attacker ko yeh nahi pata hota, isliye site CSRF style attacks se protected hoti hai.
