Help - Cryptographic Problems

Parichay (About)

Cryptography security ka ek bohot important area hai jo secrets ko secret rakhne ke liye use hota hai. Jab ise theek se implement na kiya jaye toh yeh secrets leak ho sakte hain ya fir crypto ke sath manipulation karke protections ko bypass kiya ja sakta hai.

Yeh module teen weaknesses par dhyan dega: encryption ki jagah encoding use karna, aisi algorithms use karna jinmein known weaknesses hoti hain, aur padding oracle attacks.



Objective (lakshya)

Har level ka apna ek objective hota hai lekin general idea weak cryptographic implementations ko exploit karna hai.



Low Level

Jo cheez aapko notice karni chahiye woh hai encryption ki jagah encoding ka mention, isse aapko yahan ki vulnerability ka hint mil jana chahiye.

Kuch messages ko encode karke aur unke output ko dekh kar start karein, agar aapne encoding standards ke sath thoda bhi waqt bitaya hai toh aap samajh jayenge ki yeh Base64 hai. Kya yeh itna simple ho sakta hai? Yeh pata lagane ke liye kuch test strings ko Base64 decode karke try karein:

encode (hello) -> HwQPBBs=
base64decode (HwQPBBs=) -> 0x1f 0x04 0x0f 0x04 0x1b
encode (a secret) -> FkEQDRcFChs=
base64decode (FkEQDRcFChs=) -> 0x16 0x41 0x10 0x0d 0x17 0x05 0x0a 0x1b

Woh fail ho gaya, lekin aap yeh notice kar sakte hain ki output characters ki counting input characters ke barabar hai. Ek aur common encoding method jise kabhi-kabhi encryption samajh liya jata hai woh hai XOR, yeh clear text input leta hai aur har character ko ek key ke sath XOR karta hai jo ya toh repeat hoti hai ya input jitni length ki banane ke liye truncate ki jati hai.

XOR associative hota hai, iska matlab yeh hai ki agar aap clear text ko key ke sath XOR karenge toh cipher text milega aur agar aap cipher text ko key ke sath XOR karenge toh clear text milega, iska yeh bhi matlab hai ki agar aap clear text ko cipher text ke sath XOR karenge, toh aapko key mil jayegi. Chaliye ise apne examples ke sath try karte hain: 

encode (hello) -> HwQPBBs=
xor (HwQPBBs=, hello) -> wacht

Yeh kaafi promising lag raha hai, chaliye second example try karte hain: 

encode (a secret) -> FkEQDRcFChs=
xor (FkEQDRcFChs=, a secret) -> wachtwoo

Key mein abhi tak koi repetition nahi hai toh chaliye ek lambi string ke sath try karte hain. 

encode (thisisaverylongstringtofindthepassword) -> AwkKGx0EDhkXFg4NDAYTBBsdGwoQFQwOHRkLGxoBBwAQGwMYHQs=
xor (thisisaverylongstringtofindthepassword, base64decode (AwkKGx0EDhkXFg4NDAYTBBsdGwoQFQwOHRkLGxoBBwAQGwMYHQs=)) -> wachtwoordwachtwoordwachtwoordwachtwoo

Lagta hai humein apni key "wachtwoord" mil gayi hai. Chaliye ise apni challenge string par try karke dekhte hain: 

xor (base64decode(Lg4WGlQZChhSFBYSEB8bBQtPGxdNQSwEHREOAQY=), wachtwoord) -> Your new password is: Olifant

Aur yeh lijiye, woh message jo hum dhoond rahe the aur woh password jo login karne ke liye chahiye.

Yahan ek aur seekh milti hai, yeh assume mat kariye ki messages ya underlying system jiske sath aap kaam kar rahe hain woh English mein hi hai. Key "wachtwoord" password ke liye Dutch word hai.

Medium Level

Tokens ko Electronic Code Book based algorithm (AES-128-ECB) ka use karke encrypt kiya gaya hai. Is mode mein, clear text ko fixed-size blocks mein toda jata hai aur har block ko baakiyon se independent-ly encrypt kiya jata hai. Iska result yeh hota hai ki ek aisa cipher text banta hai jo kai individual blocks se mil kar banta hai jinko aapas mein connect karne ka koi tareeqa nahi hota. Isse bhi buri baat yeh hai ki kisi bhi do clear text inputs ke koi bhi do blocks aapas mein exchange kiye ja sakte hain jab tak unhein same key ke sath encrypt kiya gaya ho. Hamare example mein, iska matlab hai ki aap apni khud ki token banane ke liye teen alag-alag tokens ke blocks le sakte hain.

Aapko block size kaise pata chalta hai? Yeh algorithm ke naam mein hi diya hota hai. aes-128-ebc ek 128 bit block cipher hai. 128 bits 16 bytes hote hain, lekin cheezon ko human readable banane ke liye, bytes ko hex characters ke roop mein represent kiya jata hai jiska matlab hai ki har byte do characters ki hoti hai. Isse aapko 32 characters ka block size milta hai. Sooty ka token 192 characters lamba hai, 192 / 32 = 6 aur isiliye Sooty ke token mein 6 code blocks hain.

Yeh maante hue ki hamare mappings sahi hain, agar aap match hone wale blocks ko compare karenge toh aap dekh sakte hain ki Sooty aur Sweep dono ka expiry block same hai (b85bb230876912bf3c66e50758b222d0) aur Sweep aur Soo dono ka level block same hai (83f2d277d9e5fb9a951e74bee57c77a3). Yeh tokens ke baare mein hum jo jaante hain usse match karta hai kyunki Sooty aur Sweep dono ke expired tokens hain aur Sweep aur Soo dono users hain, admins nahi.

Yeh sab jaan kar, ab hum apna forged session token create kar sakte hain. Humein Sweep se username block, Soo se expiry block aur Sooty se level block lena hoga. Fir hum kisi bhi token ke baaki bache blocks se token ko finish kar sakte hain. Isse humein milta hai:

873580b2e3e494ace1e9e8035f0e7e07

Jisse humein milta hai...

Yeh ek bohot hi contrived setup hai jismein tokens ko JSON object ke sath blocks map karne ke liye tweak kiya gaya hai taaki manipulation karna aasan ho, real world mein yeh itna aasan hona unlikely hai halanki kyunki data aksar fixed sized blocks se banta hai isliye overlaps is tarah ho sakte hain ki blocks ko mix karne se valid data mil jaye. Kabhi-kabhi sirf invalid data pass karne ki capability hi kaafi hoti hai isliye sirf itna karna hota hai ki blocks ko is tarah swap kiya jaye ki unhein decrypt kiya ja sake aur fir system ke baaki hisse mein pass kiya ja sake jahan woh errors paida karenge.

Agar aap iske sath thoda aur khelna chahte hain, toh sources directory mein ecb_attack.php naam ki ek script hai jo yeh dikhati hai ki tokens kaise generate hue the aur aapko custom tokens create karne ke liye unhein alag-alag tarah se combine karne deti hai.

High Level

System AES-128-CBC use kar raha hai jiska matlab hai ki yeh padding oracle attack ke liye vulnerable hai.

Ise yahan explain karne ki koshish karne ke bajaye, Eli Sohl dwara attack par likha gaya yeh behtareen write up padhein.

Impossible Level

Crypto mein aap kabhi "impossible" nahi bol sakte kyunki jo cheez aaj saalon le sakti hai woh future mein minutes mein ho sakti hai jab koi naya attack milta hai ya jab processing power ek bada leap leti hai.

AES-CBC ka current recommended alternative AES-GCM hai aur isiliye system yahan wahi use karta hai. 128 bit blocks ki jagah 256 bit blocks use kiye jaate hain, aur har message ke liye ek unique IV use hota hai. Yeh aaj secure ho sakta hai lekin kaun jaane kal kya le kar aaye?
