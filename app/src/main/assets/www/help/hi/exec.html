Help - Command Injection

परिचय (About)

command injection अटैक का उद्देश्य असुरक्षित एप्लीकेशन में अटacker द्वारा बताए गए कमांड्स को इंजेक्ट और एग्जीक्यूट करना है। ऐसी स्थिति में, जो एप्लीकेशन अनचाहे system commands को एग्जीक्यूट करती है, वह एक pseudo system shell की तरह होती है, और अटacker इसका इस्तेमाल किसी अधिकृत system user की तरह कर सकता है। हालांकि, कमांड्स वही privileges और environment के साथ एग्जीक्यूट होते हैं जो web service के पास होते हैं।

Command injection attacks ज्यादातर मामलों में सही input data validation की कमी के कारण संभव होते हैं, जिन्हें अटacker द्वारा मैनिपुलेट किया जा सकता है (फॉर्म्स, cookies, HTTP headers आदि)।

Operating Systems (OS) जैसे कि Linux और Windows में उनके इच्छित actions के आधार पर syntax और commands अलग-अलग हो सकते हैं।

इस attack को "Remote Command Execution (RCE)" भी कहा जा सकता है।



उद्देश्य (Objective)

RCE के जरिए रिमोटली OS पर web service के user का पता लगाएं, साथ ही machine के hostname का भी पता लगाएं।



Low Level

यह कई PHP functions में से किसी एक में सीधे input की अनुमति देता है जो OS पर commands को एग्जीक्यूट करेंगे। डिज़ाइन किए गए कमांड से बाहर निकलकर अनचाहे actions को एग्जीक्यूट करना संभव है।

यह request में यह जोड़कर किया जा सकता है, "एक बार कमांड सफलतापूर्वक एग्जीक्यूट हो जाने के बाद, इस कमांड को रन करें"। 

Spoiler (जवाब): To add a command "&&". Example: 127.0.0.1 && dir.

Medium Level

डवलपर ने command injection की कुछ समस्याओं के बारे में पढ़ा है, और input को फ़िल्टर करने के लिए अलग-अलग pattern patching लगाई है। हालांकि, यह काफी नहीं है।

इच्छित कमांड से बाहर निकलने के लिए अलग-अलग अन्य system syntaxes का उपयोग किया जा सकता है।

Spoiler (जवाब): e.g. background the ping command.

High Level

High level में, डवलपर दोबारा सोच-विचार करता है और मैच करने के लिए और भी ज़्यादा patterns लगाता है। लेकिन यह भी काफी नहीं है।

डवलपर से filters में शायद कोई छोटी सी टाइपिंग की गलती हो गई है और उसे लगता है कि एक निश्चित PHP command उसे इस गलती से बचा लेगी।

Spoiler (जवाब): trim()
			removes all leading & trailing spaces, right?.

Impossible Level

Impossible level में, चैलेंज को दोबारा लिखा गया है, ताकि केवल बहुत सख्त input की ही अनुमति मिल सके। यदि यह मैच नहीं होता है और एक निश्चित परिणाम उत्पन्न नहीं करता है, तो इसे एग्जीक्यूट होने की अनुमति नहीं दी जाएगी। "ब्लैक लिस्टिंग" फ़िल्टरिंग (किसी भी input की अनुमति देना और अनचाहे को हटाना) के बजाय, यह "व्हाइट लिस्टिंग" (केवल कुछ निश्चित वैल्यूज़ की अनुमति देना) का उपयोग करता है।
