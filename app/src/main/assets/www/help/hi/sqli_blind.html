Help - SQL Injection (Blind)

परिचय (About)

जब कोई हमलावर SQL Injection हमले करता है, तो कभी-कभी सर्वर डेटाबेस सर्वर से ऐसे एरर मैसेज के साथ जवाब देता है जिसमें शिकायत होती है कि SQL query का सिंटैक्स गलत है। Blind SQL Injection सामान्य SQL Injection जैसा ही होता है, सिवाय इसके कि जब कोई हमलावर किसी एप्लीकेशन का फायदा उठाने की कोशिश करता है, तो उपयोगी एरर मैसेज मिलने के बजाय, उसे डेवलपर द्वारा तय किया गया एक सामान्य पेज मिलता है। इससे संभावित SQL Injection हमले का फायदा उठाना अधिक कठिन हो जाता है लेकिन असंभव नहीं होता। हम हमलावर SQL statements के ज़रिए True और False सवालों की एक श्रृंखला पूछकर और वेब एप्लीकेशन के जवाब (वैलिड एंट्री लौटना या 404 header सेट होना) पर नज़र रखकर अभी भी डेटा चुरा सकता है।

"time based" injection मेथड का इस्तेमाल अक्सर तब किया जाता है जब पेज के जवाब में कोई विज़ुअल फीडबैक नहीं मिलता (इसलिए यह एक blind attack है)। इसका मतलब है कि हमलावर यह देखने के लिए इंतज़ार करेगा कि पेज को जवाब देने में कितना समय लगता है। अगर इसमें सामान्य से अधिक समय लगता है, तो उनकी query सफल रही।



उद्देश्य (Objective)

Blind SQL attack के ज़रिए SQL डेटाबेस सॉफ्टवेयर का वर्ज़न ढूँढें।



Low Level

यह SQL query RAW input का इस्तेमाल करती है जिसे सीधे हमलावर द्वारा नियंत्रित किया जाता है। उन्हें बस query को escape करना है और फिर वे अपनी इच्छानुसार कोई भी SQL query execute करने में सक्षम हो जाते हैं।

Spoiler (जवाब): ?id=1' AND sleep 5&Submit=Submit.

Medium Level

Medium level में "mysql_real_escape_string()" फंक्शन के साथ SQL injection सुरक्षा के एक रूप का इस्तेमाल किया जाता है। हालांकि SQL query में पैरामीटर के आस-पास कोट्स (quotes) न होने के कारण, यह query को बदलने से पूरी तरह सुरक्षित नहीं रख पाएगा।

टेक्स्ट बॉक्स को एक पहले से तय ड्रॉपडाउन लिस्ट से बदल दिया गया है और फॉर्म सबमिट करने के लिए POST का इस्तेमाल किया जाता है।

Spoiler (जवाब): ?id=1 AND sleep 3&Submit=Submit.

High Level

यह Low level के बहुत समान है, हालांकि इस बार हमलावर अलग तरीके से वैल्यू इनपुट कर रहा है। इनपुट वैल्यूज़ को GET request के बजाय किसी दूसरे पेज पर सेट किया जा रहा है।

Spoiler (जवाब): ID: 1' AND sleep 10&Submit=Submit.

Impossible Level

अब queries parameterized queries (dynamic होने के बजाय) हैं। इसका मतलब है कि query को डेवलपर द्वारा तय किया गया है, और यह अंतर करता है कि कौन से हिस्से कोड हैं, और बाकी डेटा है।
